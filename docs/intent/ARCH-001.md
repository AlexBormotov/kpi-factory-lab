# ARCH-001 — Один деплой-юнит: локальный Python-станок

Уровень документа: **deployable unit** (один запуск на машине, без сервера). Capability- и feature-документы не нужны: отдельных переиспользуемых сервисов нет.

Опирается на: `REQ-001`.

## Что это за юнит

Один Python-пакет в репозитории `test`. Вход — CSV. Выход — таблица KPI, JSON отчёта pytest, один HTML-файл. Зависимость: стандартная библиотека + `pytest`. Даты — строки `YYYY-MM-DD`, без таймзоны.

## Компоненты (имена = символы в коде)

| Имя в коде | Файл | Роль |
|---|---|---|
| `generate` | `generate.py` | Один раз создаёт сырьё и пустой шаблон эталона. Потом заморожен. |
| `kpi.calculator.calculate_kpi` | `kpi/calculator.py` | Единственная поверхность правок агента после первого прогона. |
| `kpi.report.write_dashboard` | `kpi/report.py` | Собирает HTML из уже посчитанной таблицы и `output/pytest.json`. |
| `kpi.evidence.write_pytest_report` | `kpi/evidence.py` | После pytest пишет `output/pytest.json` (счётчики, SHA). Не оракул, только улика. |
| `tests.test_kpi` | `tests/test_kpi.py` | Оракул: сравнение с `expected/kpi.csv`. |

Витрина не является калькулятором. `write_dashboard` только читает файлы.

## Контракты

**clicks.csv:** колонки `campaign,day,cost,is_bot`. `is_bot` — `true`/`false`. Одна строка = один клик.

**conversions.csv:** колонки `campaign,day,payout,type`. `purchase` идёт в Revenue, любое другое значение — нет.

**expected/kpi.csv:** колонки `campaign,day,cost,revenue`. Одна строка = одна пара кампания × день. Пустые `cost`/`revenue` означают «человек ещё не заполнил»; тогда оракул не зелёный.

**output/kpi.csv:** тот же разрез, плюс `profit,roi`, пишет калькулятор.

**output/pytest.json:** `passed`, `failed`, `sha`, `started_at`. Дашборд не имеет права вызывать pytest.

Идемпотентность: повторный `generate.py` перезаписывает фикстуры. После заполнения эталона генератор не запускать — эталон привязан к конкретным CSV.

## Decision records

### D1. Оракул — файл эталона, не модель

Нужно было решить, кто отвечает «числа правильные». ИИ-проверка или «чистка» CSV дала бы автору и судье одну природу.

Выбрано: человек заполняет Cost/Revenue; pytest сравнивает; модель не пишет эталон.

Цена: эталон не появится, пока человек не посчитает до 9 строк. Автономия на заполнение эталона не выдаётся.

### D2. Витрина — статический HTML, не сервер

Нужно было видеть KPI и pytest. Сервер добавил бы порт, второй процесс и соблазн считать на лету.

Выбрано: `write_dashboard` пишет `output/dashboard.html`.

Цена: файл надо открыть руками. Браузер может ругаться на `file://` — тогда это отдельное решение, не сейчас.

### D3. Генератор один раз, потом лёд

Нужно было сырьё без ручного набора 30+15 строк, но без контейнера раз в минуту.

Выбрано: агент пишет и один раз запускает `generate.py`, результат коммитится, скрипт замораживается.

Цена: смена сырья — человеческая операция (новый эталон). Агент не имеет права «подкрутить» CSV, чтобы тесты стали зелёными.
